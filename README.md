## 📚 About MCP & Trakt

[Model Context Protocol (MCP)](https://modelcontextprotocol.io/) enables AI models to interact with external systems through standardized tools and resources. [Trakt.tv](https://trakt.tv) is a comprehensive platform for tracking TV shows and movies with 14+ million users and extensive APIs for developers.

## 🚀 Quick Start

### Create a Trakt API app

You need your own Trakt API app to get a Client ID:

1. Go to [developer.trakt.tv](https://developer.trakt.tv) and create an app. Trakt requires a verified GitHub account for this.
2. **App type**: choose **Development** for personal use. Only you and the people you add can sign in.
3. **Redirect URIs**: enter `http://localhost`. The server signs in with the device code flow and never receives a callback, but Trakt requires at least one URI on the app.
4. **Allowed origins**: leave blank. They only apply to code running in a web browser.
5. Copy the **Client ID** into `TRAKT_CLIENT_ID`. If Trakt issued your app a Client Secret (older apps have one), set it as `TRAKT_CLIENT_SECRET`. New apps don't get one, so leave it unset.

### Docker Quickstart
```bash
docker run -d --rm --name trakt_mcpserver \
  -e TRAKT_CLIENT_ID=your_client_id \
  -v trakt_auth:/data \
  -p 8080:8080 \
  ghcr.io/wwiens/trakt_mcpserver:latest
```

### Run with uvx (no clone, no install)

Requires [uv](https://docs.astral.sh/uv/) installed.

The installed package reads credentials from environment variables only. It does not load a `.env` file, so set `TRAKT_CLIENT_ID` in the shell or in your MCP client's `env` block (see below).

```bash
TRAKT_CLIENT_ID=your_client_id uvx trakt-mcp
```

Pin to a release for reproducibility:

```bash
TRAKT_CLIENT_ID=your_client_id uvx trakt-mcp@0.11.2
```

**Claude Desktop / MCPhub configuration:**
```json
{
  "mcpServers": {
    "trakt": {
      "command": "uvx",
      "args": ["trakt-mcp"],
      "env": {
        "TRAKT_CLIENT_ID": "your_client_id"
      }
    }
  }
}
```

Your Trakt OAuth token is persisted to `~/.trakt-mcp/auth_token.json` (the directory is created on first login), so authorization survives across uvx invocations. To override the location — e.g. for Docker volumes or to keep multiple isolated accounts — set `TRAKT_AUTH_TOKEN_PATH` to an absolute path.

### Install with pip

Requires Python 3.12 or newer. As with uvx, credentials come from environment variables, not a `.env` file.

```bash
pip install trakt-mcp
TRAKT_CLIENT_ID=your_client_id trakt-mcp
```

### Local Installation

Requires Python 3.12 or newer.

1. **Clone this repository**
   ```bash
   git clone https://github.com/wwiens/trakt_mcpserver.git
   cd trakt_mcpserver
   ```

2. **Create a virtual environment and install dependencies**
   ```bash
   python3 -m venv .venv
   source .venv/bin/activate
   pip install -e .
   ```

3. **Set up your environment**
   ```bash
   cp .env.example .env
   ```
   Then edit `.env` to add your Trakt API credentials:
   ```bash
   TRAKT_CLIENT_ID=your_client_id
   ```

4. **Run the server**
   ```bash
   python server.py
   ```

### Installing in Claude Desktop
Add to your Claude Desktop MCP configuration file:
```json
{
  "mcpServers": {
    "trakt": {
      "command": "python",
      "args": ["/path/to/your/server.py"],
      "env": {
        "TRAKT_CLIENT_ID": "your_client_id"
      }
    }
  }
}
```

## ✨ Features

### 🌎 Public Trakt Data
- Access trending and popular shows and movies
- Discover the most anticipated, favorited, played, and watched content
- See the top-grossing U.S. box office movies from last weekend
- Get real-time data from Trakt's global community
- Formatted responses with titles, years, and popularity metrics
- **View detailed ratings** for shows and movies including average scores and distribution
- **Browse show seasons** with episode counts, aired episodes, and ratings per season
- **Dive into specific seasons** with detailed info, episode lists, ratings, cast & crew, videos, translations, and engagement stats
- **See who's watching** a specific season right now
- **Find lists** containing a specific season
- **Explore individual episodes** with detailed summaries, ratings, cast & crew, videos, translations, and engagement stats
- **See who's watching** a specific episode right now
- **Find lists** containing a specific episode
- **Look up cast and crew** for any movie or show, with optional guest stars for shows
- **Explore people** with biographies, social media, and full filmographies
- **Browse a person's credits** across movies and shows with character names and episode counts
- **Find lists** containing a specific person

### 👤 Personal Trakt Data
- **View Your Watched Shows**: Get a complete list of shows you've personally watched
- See your exact last-watched dates for each series
- Track how many times you've watched each show
- **Check in to shows** you're currently watching to mark them as watched
  - By show ID (more precise) or show title (more convenient)
  - Include custom messages with your check-ins
  - See when you watched the episode in human-readable format
- **Check in to movies** you're currently watching, and **cancel** an active check-in (movie or episode)
  - By movie ID, slug, or IMDB ID, or by title and year
  - If you are already checked in, the error says when you can check in again
- **Search for shows** to find their details and IDs
- **Manage your ratings**: View, add, and remove personal ratings for movies, shows, seasons, and episodes with pagination support, rating-range and date filters, and a summary mode (counts per rating plus the 20 most recent)
- **Manage your watchlist**: View, add, and remove items from your watchlist with pagination and sorting support
  - Filter by type (all, movies, shows, seasons, episodes)
  - Sort by multiple criteria (rank, added, title, released, runtime, popularity, percentage, votes)
  - Add optional notes to watchlist items (VIP feature, 500 char limit)
- **View your collection**: Fetch your whole movie or show collection in one call (all pages, no item cap)
  - Movies list collected date and, optionally, resolution, HDR and audio
  - Shows list how many episodes you have collected
- **Find what you have not watched**: `unwatched_in_collection` compares your whole movie collection with everything you have watched in one call
  - Filter by runtime, genres (include and exclude) and Trakt community rating
  - Sort by rating, runtime, collected date, release date or at random, and limit the list
  - Each line shows title, runtime, genres, rating and resolution
  - Movies only for now; shows are planned. The collection and watched set are cached for 15 minutes and refreshed when you add or remove history
- **Check if you have seen specific movies**: `have_i_seen` takes Trakt movie IDs and reports, per ID, whether you watched it, how many times, when you last watched it and your own rating
  - Uses the same cached watched history as `unwatched_in_collection`, plus your movie ratings (cached 15 minutes, refreshed when you add or remove history or ratings)
- **Manage your personal lists**: View your lists, create new ones, and add or remove movies and shows
  - Choose list privacy (private, link, friends, public) when creating a list
  - See every item on a list, however long it is
  - Adds and removals report how many items were added, already on the list, or not found
- **Track show progress**: See your watched progress for any TV show
  - View episodes watched vs aired with completion percentage
  - See your next episode to watch
  - View per-season breakdown with progress stats
  - Include hidden seasons and specials optionally
- **Manage playback progress**: View and clear paused playback items
  - See movies and episodes you paused mid-watch
  - View progress percentage and when you paused
  - Clear playback items you no longer need
- **Manage watch history**: Add and remove items from your history
  - Mark movies, shows, seasons, or episodes as watched
  - Optionally specify when you watched them
  - Remove items from your watch history
- Secure authentication with Trakt through device code flow
- Personal data is fetched directly from your Trakt account

## 🔐 Authentication

The server uses Trakt's device authentication flow:

1. When you request user-specific data, the server will automatically initiate authentication if needed
2. You'll receive a code and a URL to visit on your browser
3. After entering the code on the Trakt website and authorizing the app, inform Claude that you've completed the authorization
4. Claude will check the authentication status and then fetch your personal data
5. Your authentication token is stored securely in `~/.trakt-mcp/auth_token.json` for future requests, with `0o600` permissions. Override the location with the `TRAKT_AUTH_TOKEN_PATH` env var; Docker images set it to `/data/auth_token.json` — mount a volume at `/data` (e.g. `-v trakt_auth:/data`) to persist auth across container recreations.

You can log out at any time using the `clear_auth` tool.

| Variable | Required | Description |
|----------|----------|-------------|
| `TRAKT_CLIENT_ID` | Yes | Client ID of your Trakt API app |
| `TRAKT_CLIENT_SECRET` | No | Client Secret, if your app has one. Trakt has deprecated it for user sign-in |
| `TRAKT_REDIRECT_URI` | No | Sent when the server refreshes your token. Must be HTTPS or loopback HTTP. Defaults to `http://localhost` |
| `TRAKT_AUTH_TOKEN_PATH` | No | Where the OAuth token is stored. Defaults to `~/.trakt-mcp/auth_token.json` |

Access tokens last 7 days and refresh automatically. Refresh tokens are single-use. If a refresh fails with `invalid_grant` / `session not found` (for example, a token issued before Trakt's auth migration), run the device flow again once.

## 🌐 Transports

By default the server speaks MCP over stdio, which is what `uvx trakt-mcp`, `python server.py` and Claude Desktop use. To serve it over HTTP instead, pass `--transport http` or set `TRAKT_MCP_TRANSPORT=http`:

```bash
TRAKT_CLIENT_ID=your_client_id trakt-mcp --transport http --host 127.0.0.1 --port 8080
```

One app serves everything:

| Path | Purpose |
|------|---------|
| `/mcp` | **Streamable HTTP** (MCP spec 2025-03-26 and later). Point clients at `https://<host>/mcp` |
| `/sse` and `/messages/` | Legacy HTTP+SSE, **deprecated**: the spec replaced it with Streamable HTTP. On by default and every connection logs a warning. Migrate clients to `/mcp`, then turn it off with `TRAKT_MCP_LEGACY_SSE=false` or `--no-legacy-sse`: both paths then return `404` |
| `/healthz` | Liveness check for Docker or a reverse proxy. Needs no MCP session or login and never calls Trakt |

`/healthz` answers `200 {"status": "ok", "token": "present"}` (`"absent"` before the first login, `"expired"` once the access token has lapsed; neither is unhealthy, as logging in is a tool call). It answers `503 {"status": "error", "token": "unreadable"}` when the token file exists but cannot be read. It never returns token values.

| Variable | Default | Description |
|----------|---------|-------------|
| `TRAKT_MCP_TRANSPORT` | `stdio` | `stdio` or `http`. The `--transport` flag wins |
| `TRAKT_MCP_HOST` | `127.0.0.1` | HTTP bind address. Use `0.0.0.0` in a container. The `--host` flag wins |
| `TRAKT_MCP_PORT` | `8080` | HTTP port. The `--port` flag wins |
| `TRAKT_MCP_ALLOWED_ORIGINS` | empty | Comma-separated browser origins allowed to call `/mcp` and `/sse`, for example `https://claude.ai`. Matching is exact, so list each scheme and host |
| `TRAKT_MCP_ALLOWED_HOSTS` | empty | Comma-separated `Host` header values to accept, for example `trakt.example.com,trakt:8080`. `host:*` matches any port |
| `TRAKT_MCP_LEGACY_SSE` | `true` | `false` stops serving the deprecated `/sse` and `/messages/` routes (they return `404`) and skips their deprecation warning; `/mcp` and `/healthz` are unaffected. Accepts `true`/`false`, `1`/`0`, `yes`/`no`, any case; anything else is a usage error. The `--no-legacy-sse` flag wins |
| `TRAKT_MCP_STATELESS` | `false` | `true` keeps no per-client session, so a restart never invalidates one. The Docker image sets it |

**Origin check.** A request with no `Origin` header is accepted: that is any non-browser client, such as a reverse proxy or an OAuth gateway calling server to server. A request that carries one must match `TRAKT_MCP_ALLOWED_ORIGINS`, otherwise it gets `403`. With the variable empty, every request that carries an Origin is rejected. If claude.ai connects through a gateway that forwards its `Origin`, set `TRAKT_MCP_ALLOWED_ORIGINS=https://claude.ai`.

**Host check.** Bound to loopback with `TRAKT_MCP_ALLOWED_HOSTS` empty, only `127.0.0.1`, `localhost` and `[::1]` are accepted. Bound to any other address with it empty, the `Host` header is not checked, because the right value depends on the proxy in front. Behind a proxy that forwards `Host: trakt:8080`, set `TRAKT_MCP_ALLOWED_HOSTS=trakt:8080` to turn the check on. A rejected host gets `421`.

The server has no login of its own: expose it only behind something that authenticates callers (an OAuth gateway or a private network).

## 🐳 Docker Deployment

Two Docker images are available with different transport mechanisms. Each release also publishes a versioned tag (e.g. `:0.9.0`, `:0.9.0-stdio`) for pinning.

| Image Tag | Transport | Use Case |
|-----------|-----------|----------|
| `:latest` | Streamable HTTP (`/mcp`), legacy SSE (`/sse`) | Remote access, web clients, docker-compose |
| `:latest-stdio` | stdio | MCPhub, Claude Desktop, local MCP clients |
| `:stdio` | stdio | **Deprecated alias for `:latest-stdio` — will be removed at v1.0.0** |

### stdio Transport (MCPhub, Claude Desktop)

Use the `:latest-stdio` image (or pin a version like `:0.9.0-stdio`) for MCP clients that communicate via stdin/stdout:

```bash
# Pull and run the stdio image
docker run -i --rm --name trakt_mcpserver_stdio \
  -e TRAKT_CLIENT_ID=your_client_id \
  -v trakt_auth:/data \
  ghcr.io/wwiens/trakt_mcpserver:latest-stdio
```

**Claude Desktop configuration:**
```json
{
  "mcpServers": {
    "trakt": {
      "command": "docker",
      "args": [
        "run", "-i", "--rm", "--name", "trakt_mcpserver_stdio",
        "-e", "TRAKT_CLIENT_ID=your_client_id",
        "-v", "trakt_auth:/data",
        "ghcr.io/wwiens/trakt_mcpserver:latest-stdio"
      ]
    }
  }
}
```

### HTTP Transport (Remote)

Use the `:latest` image for HTTP-based access. Clients connect to `http://localhost:8080/mcp`; `/sse` still works but is deprecated (see [Transports](#-transports)). The image serves on `0.0.0.0:8080` and has a `HEALTHCHECK` on `/healthz`. To accept requests from a browser origin or a proxied `Host`, add `-e TRAKT_MCP_ALLOWED_ORIGINS=...` and `-e TRAKT_MCP_ALLOWED_HOSTS=...`.

```bash
# Option 1: Pull and run from GHCR (recommended)
docker run -d --rm --name trakt_mcpserver \
  -e TRAKT_CLIENT_ID=your_client_id \
  -v trakt_auth:/data \
  -p 8080:8080 \
  ghcr.io/wwiens/trakt_mcpserver:latest

# Option 2: Build locally and run
docker build -t trakt_mcpserver .
docker run -d --rm --name trakt_mcpserver \
  -e TRAKT_CLIENT_ID=your_client_id \
  -v trakt_auth:/data \
  -p 8080:8080 \
  trakt_mcpserver
```

### Using `docker compose`

`docker-compose.yml` reads credentials from `.env` in the repository root, so create it first:

```bash
cp .env.example .env  # then set TRAKT_CLIENT_ID in .env
# Builds the docker image using the default Dockerfile (HTTP variant) and starts the service
docker compose up
```

This runs the server on `http://localhost:8080`: Streamable HTTP on `/mcp` (legacy SSE on `/sse`).
